# 商店上架材料（Chrome Web Store / Edge Add-ons）

两家商店用同一个 zip：Release 页的 `apkgo-assistant-<版本>.zip`。下面的文案直接粘贴。

## 基本信息

- **名称**：密钥助手
- **一句话简介（Summary，≤132 字符）**：在华为、小米、OPPO、vivo、荣耀、应用宝开发者后台里一键取回 API 密钥，直接保存到配置平台并在线验证。只连配置平台。
- **类别**：开发者工具（Developer Tools）
- **语言**：中文（简体）
- **官网 / 支持链接**：https://github.com/hjaaa/apkgo-assistant
- **隐私政策 URL**：https://github.com/hjaaa/apkgo-assistant/blob/main/PRIVACY.md
  （仓库若不是公开的，这个链接对审核无效，上架前得把 PRIVACY.md 放到一个能公开访问的地址）
- **图标**：`icons/128.png`（商店要 128×128）

## 详细描述（Description）

密钥助手是**配置平台**（主体 → 密钥配置）的配套扩展。配置平台帮你把安装包一次提交到多家应用商店，但第一步「去每家开放平台后台拿 API 密钥」一直最麻烦：每家菜单不一样、要主账号、有的还要申请开通。这个扩展把这一步做顺：

• 打开华为、小米、OPPO、vivo、荣耀、应用宝六家开发者后台时，页面下方出现助手按钮，面板里是这家的前置条件和该点的菜单。
• 六家都支持「一键获取密钥」：小米、OPPO、vivo、荣耀直接通过后台自己的接口读出凭据并保存验证，几秒完成；华为由扩展跳到密钥页、打开创建弹窗并填好，你只需点一下「确认」；应用宝调后台同源接口取 access_secret 并从登录信息取开发者 ID。全程密钥自动抓取、保存、验证。
• 保存按 (主体, 渠道) 有则改、无则增。配置平台保存时会连一次该商店验证密钥（应用宝除外），通过才落库，结果就地显示，不用来回切页面。

安全与隐私：
• 只向你连接时所在的配置平台地址发请求，不连任何第三方。
• 采集到的密钥只在浏览器会话内存里暂存（`chrome.storage.session`），保存成功立即清除，从不落盘。
• 连接时网页交给扩展的是你当前的登录令牌（与网页 cookie 里的是同一把），权限等同于你本人在平台上的权限；存于扩展本地存储，可在扩展弹窗点「断开连接」随时删除，令牌失效时扩展也会自动清除。
• 当前配置平台是内网 HTTP，令牌与密钥以明文在内网传输，仅适用于可信内网环境。
• 开源（MIT），可复现构建：发布的 zip 与 GitHub Release 的字节一致，附 sha256。

使用前需要一个配置平台账号：http://inner.dreamplatform.cn:18003

## 权限用途说明（商店审核会问）

| 权限 | 用途 |
|---|---|
| `storage` | 保存连接配置平台的登录令牌（local）和采集中的密钥草稿（session，关浏览器即清）。 |
| `scripting` | 在商店后台页面注入一个下载钩子（主世界），页面下载密钥文件时把内容填进面板，免去文件对话框。只读页面自己发起的下载。 |
| `downloads` | 识别刚发生的密钥文件下载（.json/.cer/.pem/.p8/.key），配合钩子；不读取其他下载。 |
| 页面返回记录器 | 在商店后台页面自己的世界里暂存该页面发出的 JSON 返回（40 条 / 64KB 上限，关页即清），仅在用户点「一键获取密钥」后读取声明好的字段（如应用宝的开发者 ID），其余丢弃、不外发。|
| 各商店后台域名（host permissions） | 只列已适配的六家（华为、小米、OPPO、vivo、荣耀、应用宝）的开发者后台域名，用于显示助手面板并按用户操作读取密钥字段。没有 `<all_urls>`。 |
| `http://inner.dreamplatform.cn:18003/*`、`http://192.168.1.18:16003/*`、`http://localhost/*` | 让配置平台网页把登录令牌交给扩展。第一个是生产，后两个供内网联调与本地开发。配对时以页面自身的 origin 为准，网页无法把扩展指向别的地址。 |

远程代码：无。扩展不加载任何远程脚本。

数据使用声明（Chrome Web Store「隐私权规范」表单）：
- 收集「身份验证信息」（商店 API 密钥、配置平台登录令牌）：是；用途仅为扩展的核心功能；不出售、不用于与核心功能无关的目的、不用于信用评估。
- 其余类别（个人信息、健康、财务、位置、网络历史、用户活动、网站内容）：否。

帮助配置平台用户从各应用商店开放平台后台获取 API 密钥并保存到配置平台。

## 提交流程

首次上架必须在两家后台手动做一次（注册开发者、建条目、填商店列表与隐私表单、传截图）。自动发布工作流已删除，每个版本打 tag 由 `release.yml` 出 zip，再手动传到两家后台。

### Chrome Web Store

后台：https://chrome.google.com/webstore/devconsole

1. Google 账号注册开发者，一次性 5 美元。
2. 「新增项目」→ 上传 `apkgo-assistant-<版本>.zip`（Release 页下载，别自己重新打包）。
3. **商店发布信息**：名称、简介、详细描述、类别「开发者工具」、语言「中文（简体）」，图标 128×128，截图 5 张，小宣传图 440×280（可选）。
4. **隐私权规范**（审核最容易卡的一页，逐项对应本文上面的段落）：
   - 单一用途说明
   - 每个权限的用途：`storage`、`scripting`、`downloads`、六家商店后台域名、配置平台地址
   - 远程代码：**否**（扩展不加载任何远程脚本）
   - 数据用途：勾「身份验证信息」，用途只勾「实现扩展的单一用途」；不出售、不用于无关用途、不用于信用评估
   - 隐私政策 URL：见上面「基本信息」
5. 提交审核，通常 1–3 个工作日。

### Edge Add-ons

后台：https://partner.microsoft.com/dashboard/microsoftedge

1. 微软账号注册 Partner Center，免费。
2. 「创建新扩展」→ 上传**同一个 zip**。
3. 「可用性」选公开与目标市场；「属性」填类别、隐私政策 URL、支持链接（仓库地址）。
4. 「商店列表」填名称、简介、描述、截图。
5. 提交认证，通常 1–7 个工作日。

### 上架之后

把两个商店链接填进配置平台前端的扩展安装引导处，替换掉现在「下载 zip 手动加载」的说明。

### 审核可能被问到的两件事

- **为什么需要读取商店后台页面？** 扩展的唯一功能就是在这些页面上帮用户取回他自己的 API 密钥；host 权限只申请了这六家后台加配置平台自己的地址，没有 `<all_urls>`。
- **为什么会读取页面的接口返回和本地存储？** 部分后台（应用宝）把开发者 ID 只放在自己的接口返回和 `localStorage` 里。助手仅在用户点「一键获取密钥」后读取，且只取声明好的字段，其余立即丢弃，不外发、不落盘。详见隐私说明。
